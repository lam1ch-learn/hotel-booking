# Устройство и решения

## Таблицы

| Сервис / таблица | Основные поля и ограничения |
|---|---|
| Booking / `users` | `id`, уникальный `username`, хеш `password`, `role` |
| Booking / `bookings` | UUID `id`, FK `user_id`, `request_id`, `room_id`, даты, статус, `created_at`; уникальность `(user_id, request_id)` |
| Hotel / `hotels` | `id`, `name`, `address` |
| Hotel / `rooms` | `id`, FK `hotel_id`, `number`, `available`, `times_booked`, `version`; уникальность `(hotel_id, number)` |
| Hotel / `room_reservations` | `booking_id`, FK `room_id`, даты, `released`; индекс номера и дат |

Дополнительные поля Booking: `auto_select`, `requested_room_id`, `hotel_id` — для проверки повторного запроса; `release_pending` — для повторной компенсации; `version` — защита обновлений. Есть индексы владельца/времени и статуса/времени. Межсервисных внешних ключей нет: каждый сервис владеет своей БД.

Hotel хранит локальную проекцию периодов бронирований в `room_reservations`. Проверка дат не обращается к чужой БД. `available` описывает только техническую доступность номера. По условию отдельная H2 есть и у Gateway с Eureka, но бизнес-таблиц в них нет: эти приложения отвечают только за инфраструктуру.

## ADR 1. Локальные транзакции вместо общей

Booking сохраняет `PENDING` и завершает транзакцию. Затем вызывает Hotel, который в своей транзакции блокирует строку номера, проверяет пересечение `[заезд, выезд)` и создаёт слот. После ответа Booking отдельной транзакцией ставит `CONFIRMED`.

При ошибке Booking сохраняет `CANCELLED` и признак незавершённой компенсации. Затем вызывает release. Если Hotel всё ещё недоступен, фоновая задача повторяет отмену. Старые `PENDING` тоже отменяются. HTTP-вызовы не выполняются под транзакцией Booking.

Одна попытка обращения ограничена connect/read timeout. Повторяются только сетевые сбои и 5xx, с растущей паузой и ограничением попыток. 4xx не повторяются. Circuit Breaker закрывает подтверждения при частых сбоях; компенсация обходит его, но сохраняет тайм-ауты и ограничения повторов. Иначе открытый circuit мешал бы освободить номер.

## ADR 2. Идемпотентность и гонки

Клиент задаёт `requestId`; уникальность действует в рамках пользователя. Короткая блокировка строки пользователя сериализует создание одинаковых запросов. Та же пара ключей с другим содержимым даёт 409. Повтор уже выполняющегося запроса видит `PENDING`, а не запускает второй процесс.

Для Hotel ключ — `bookingId`. Проверка занятости и запись выполняются под `PESSIMISTIC_WRITE` на номере. Блокировка в БД работает и при нескольких экземплярах сервиса с общей БД. Отмена сохраняет запись `released=true`, даже если подтверждение ещё не пришло. Поздний confirm эту отмену не отменяет. Смены статуса Booking тоже защищены блокировкой строки.

H2 хранит данные в памяти и теряет их при перезапуске. Повтор отмены помогает при сбоях HTTP, но не при потере БД. Для постоянного сервиса понадобятся обычная БД и сохранение задач на отмену.

## ADR 3. JWT и границы сервисов

Booking подписывает JWT приватным RSA-ключом. Hotel и Gateway получают только публичный ключ и проверяют подпись, issuer, audience и срок. Внутренний токен SERVICE выдаётся только кодом Booking; у публичного API нет регистрации этой роли. Контроллеры используют `@PreAuthorize`, Gateway блокирует внутренние пути независимо от роли.

Eureka — инфраструктурный реестр в локальном стенде, без пользовательских операций и JWT. При размещении вне ноутбука ему нужны отдельная сеть и защита транспорта; все сервисы сейчас привязаны к localhost. Тестовые PEM в `src/test/resources` используются только тестами. Рабочие ключи генерируются заново и исключены из Git.

## ADR 4. Минимум слоёв, но разные обязанности

HTTP-контроллеры принимают DTO. Сервисы меняют доменные объекты через их методы. Репозитории отвечают за выборки и блокировки. BookingStore выделен отдельно, чтобы транзакции гарантированно завершались до вызова Hotel и не зависели от self-invocation Spring-прокси. Сетевой клиент заменяем через интерфейс. Остальным сервисам интерфейсы с единственной реализацией не добавлены.

Имена путей приведены к общему REST-виду `/api/...`; в задании пути примерные. Изменение дат брони выполняется отменой и новым созданием: дополнительного неоговорённого состояния для редактирования нет.
